# 未發布：收尾規則寫入 .agt/README.md、收尾預覽提醒

類型：新增（MINOR）。發布時把下面這一行併入 `CHANGELOG.md` 的「未發布 → 新增」，並刪除這個檔案。

## CHANGELOG 條目

- 收尾規則改由 agt 提供：建立分頁時在 worktree 寫入 `.agt/README.md`（說明檔格式、多個主題時如何分組），Agent 提示只需要叫它先讀這個檔案。收尾視窗會提醒 `.agt/` 裡 agt 不認得的項目（例如 Agent 自己寫的 `split/`），以及改動很大卻沒有分組的情況；`agt config check` 會提醒提示沒有提到收尾規則的 `auto_commit` Agent

## 細節

- **為什麼**：收尾規則原本只寫在使用者設定檔的 Agent 提示裡，升級 agt 不會跟著更新。用舊提示的 Agent 不知道有 `.agt/groups/`，自己寫了 agt 不認得的 `.agt/split/` 拆分計畫，收尾時全部放進同一個 PR，而且沒有任何提醒。
- `.agt/README.md`：每次建立有 worktree 的分頁時寫入（覆寫舊的；`.agt` 是連結時拒絕，不跟隨連結）。內容在 `crates/agt-git/src/agent_guide.md`，除了格式，也說明分組做不到的情況（同一個檔案、彼此依賴）要怎麼處理，以及「一個分頁一個主題」。建立於這個版本之前的分頁不會有這個檔案。
- 收尾預覽最前面的 `⚠` 提醒（紅色）：
  - `.agt/` 底下 `README.md`、`COMMIT_MSG`、`PR_BODY.md`、`groups` 以外的項目（最多列 5 個）。
  - 沒有分組，且相對 merge-base 的改動超過 40 個檔案或 1500 行（新增 + 刪除，含已 commit 與未 commit；未追蹤的檔案只算檔案數）。
- `agt config check`：`auto_commit = true` 且使用 worktree 的 Agent，`args`／`restart_args`／`extra_args`／`new_args` 都沒有提到 `.agt/README.md`（或舊版提示的 `.agt/groups`）時發出警告。
- `config/default.toml` 的 `claude-docker`、`claude-sbx` 範例提示：分組的長段說明改成「完整的收尾規則在 .agt/README.md，開始修改前先讀」。**已經複製舊版範例的設定檔不會自動更新**，`agt config check` 會提醒。
