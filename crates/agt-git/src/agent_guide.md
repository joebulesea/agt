# agt 收尾規則（給 Agent）

這個檔案由 agt 在建立分頁時寫入，每次建立都會覆寫；不要修改它。
`.agt/` 目錄不會被 commit，也不會出現在 diff 裡。

使用者在 agt 按「收尾」（merge 或 pr）時，agt 會依照你在 `.agt/` 留下的說明檔
commit、合併或開 PR。**agt 只認得下面列出的檔案與目錄**，其他名稱（例如 `.agt/split/`、
`.agt/plan/`）會被忽略，裡面的內容不會被用到。

## 只有一個主題（大多數情況）

每次完成修改後更新這兩個檔案（已存在時改寫成涵蓋目前所有未 commit 修改的內容）：

- `.agt/COMMIT_MSG`：第一行是 50 字以內的標題，空一行後是內文。
- `.agt/PR_BODY.md`：Markdown，寫做了什麼、為什麼、如何測試。

## 有多個互不相關的主題：分組

每組建立 `.agt/groups/<組名>/`，放：

- `FILES`：這組包含的路徑，一行一個，相對於專案根目錄；寫目錄代表底下全部。刪除的檔案也要列出。
- `COMMIT_MSG`、`PR_BODY.md`：格式同上（第一行同時是 PR 標題）。
- `AFTER`（選用）：這組用到另一組新增的程式碼時，寫那一組的組名（一行）。

收尾時每組各自一個 commit（pr 則各自一個 branch 與 PR）。沒有被任何組列出的變更，
會自動成為最後一組 `rest`。分組時不需要再寫最外層的 `.agt/COMMIT_MSG`、`.agt/PR_BODY.md`。

規則：

- 組名只能用英數字與 `.`、`_`、`-`，最長 40 字，不能以 `.` 或 `-` 開頭，不能叫 `rest`。
- **同一個檔案只能屬於一組**，以整個檔案為單位，無法把一個檔案裡的不同段落分到不同組。
- **沒有 `AFTER` 的組各自從 base 建立，彼此不包含對方的變更。** 某組用到另一組新增的程式碼時，
  在它的 `AFTER` 寫上那一組：它會接在那組後面建立，PR 的 base 也是那組的 branch（堆疊 PR，
  那組合併後才合併這組）。`AFTER` 可以串成一條鏈（a ← b ← c），但不能形成循環。

## 多個主題改到同一個檔案時

一個檔案只能屬於一組。做不到的拆分，**不要另外寫拆分計畫或要使用者手動挑選段落**。改成：

1. 把改到同一個檔案的主題放在同一組（或乾脆不分組）。
2. 在那一組的 `PR_BODY.md` 開頭列出包含哪些主題，並說明為什麼沒有拆開。

只是「B 用到 A 新增的程式碼」、但沒有改到同一個檔案時，不需要合併成一組：B 寫 `AFTER`（內容 `A`）即可。

## 避免累積太多主題

一個分頁最好只做一個主題。使用者要求的事情和目前的修改無關時，先提醒他：
可以先收尾目前的修改，再開新分頁做下一個主題。這比事後再拆容易得多。
